# Styling

How the interface is coloured and how controls are built. Read this before adding a
button, a toggle, a tag chip, or a colour.

There is **no `tailwind.config.*`** and there never needs to be. Tailwind 4 is wired
in through `@tailwindcss/vite` (`vite.config.ts`) and configured entirely by the
`@theme` block in `src/styles.css`, which is the only stylesheet in the project.

---

## 1. Tokens

Every colour is a `--color-*` token in `@theme`. Tailwind generates `bg-*`,
`text-*`, `border-*` utilities from each one automatically, so a new token needs no
other registration.

**Six are user-editable.** They are exposed in Settings → Appearance and persisted
to `Config.colors` (`ColorOverrides` in `lib/types.ts`):

| Key | Token | Shown to the user as |
|---|---|---|
| `bg` | `--color-bg` | background |
| `src` | `--color-src-bg` | panel bg |
| `text` | `--color-text` | text |
| `accent` | `--color-accent` | accent |
| `handle` | `--color-handle` | handles |
| `border` | `--color-border` | border |

`applyColors()` in `lib/colors.ts` writes them onto `document.documentElement` at
startup (`lib/bootstrap.ts`) and again on every live edit in `SettingsDialog`. It
always sets explicit values and never removes a property, so a utility always
resolves.

### Derived tokens

`applyColors()` also fans out. Setting `bg` writes `--color-panel`,
`--color-surface` and `--color-gallery-surface`; setting `src` writes
`--color-inset`. **Do not add a new alias of `bg`** — the three that exist are
already three names for one value.

Setting `accent` derives three more, and these are what controls are built from:

| Token | How | Used for |
|---|---|---|
| `--color-accent-muted` | accent converted to HSL, **saturation × 0.5**, same hue and lightness | the fill on every button |
| `--color-on-accent` | black or white, whichever contrasts better with the accent | text on a selected control |
| `--color-on-accent-muted` | the same choice made against the *muted* accent | text on a button |

The two `on-*` tokens are separate on purpose. Halving saturation shifts luminance,
so the accent and its muted form can fall on opposite sides of the black/white
crossover — the default `#9b31f2` takes white while its muted form `#9661c2` takes
black. One shared token would leave one of the two surfaces below AA contrast.

`readableOn()` returns `null` for anything it cannot parse as hex. That matters:
`UNKNOWN_TAG_COLOR` (`stores/tagsStore.ts`) is the literal string
`"var(--color-dim)"` and reaches `Chip` through `tagColor()`. Callers must fall
back to inheriting rather than assuming a colour comes back.

The defaults hardcoded in `@theme` are exactly what the derivation produces for the
default accent, so the first paint matches what `applyColors()` will set.

## 2. Controls

**Use a primitive. Do not inline button styling.** That rule is the whole point of
this section — the alternative was 137 hand-styled buttons across 45 files with six
competing "secondary" surfaces and five different ways to say "selected".

| Primitive | Use it for |
|---|---|
| `Btn` | any button with a text label |
| `Chip` | a tag or filter chip |
| `IconBtn` | a button whose whole content is one icon |
| `ToggleGroup` | a row of mutually exclusive options (built on `Btn`) |

### `Btn`

Capsule geometry, accent-derived fill, one disabled treatment.

- `variant="solid"` (default) — a plain action. Muted-accent fill.
- `variant="toggle"` with `active` — reads as `solid` when off and brightens to the
  full accent when on. Sets `aria-pressed`.
- `variant="ghost"` — text only, no fill or capsule. For disclosures, tab strips and
  inline text links, where a pill would be wrong.
- `size="sm"` (default) suits the app's dense rows; `size="md"` suits modal footers.

Unselected `toggle` and `solid` share a fill deliberately: an unselected toggle
should read as a button, and selecting it brightens.

### `Chip`

A selected chip fills with **the tag's own colour**, not the accent, so a bar of
active filters stays readable as a vocabulary. The colour dot is dropped in that
state because the fill already carries it. Chips that aren't tags — the
"generated by" user filters — pass no `color` and fall back to the accent.

### `IconBtn`

Icon buttons are **not** capsules and are **not** filled. They keep a ghost
treatment, take the accent on hover, and show `active` as an accent glyph. A row of
gallery-toolbar icons has to read as a strip; a run of pills would break it.

## 3. Deliberate exceptions

Not everything is a capsule, and these are decisions rather than misses:

- **The gallery toolbar strip** (`Gallery.tsx`) — contiguous square icon buttons.
  Selected is a full-accent fill, which satisfies the rule without breaking the run.
- **Menu and list rows** — `PathContextMenu`, `LogWindow`, `RoleMenu`, the
  suggestion rows in `TagEditorPopup`. A full-width dropdown row is not a pill.
- **Column chrome** — `CollapsedColumnBar`, `GalleryColumn` headers, `StackedView`
  row labels.
- **Colour that encodes data** — SAM's green/red foreground-background point labels
  (`SamPromptModal`), and `text-ok` / `text-warn` / `text-bad` status text. This is
  information, not chrome, and must not be flattened to the accent.
- **Tabs** (`TabBar`) — marked with an accent underline rather than a fill, because
  the tab label's colour already reports queued and unseen work. Same idiom as the
  Settings tab strip.
- **Inputs** — `<input>`, `<select>`, `<textarea>` stay square. Only controls you
  press are capsules. Native checkboxes and radios use `accent-accent`.

---

## 4. Known gaps

- **`bg-bg`, `bg-panel` and `bg-surface` are three names for one runtime value.**
  They can never visually differ. Collapsing them is safe but touches far more than
  any one change has needed to.
- **Raw Tailwind palette colours bypass the theme** in about 50 places
  (`text-red-500`, `text-white`, `bg-white`, `border-white`), while the
  `--color-ok` / `--color-warn` / `--color-bad` tokens that exist for exactly this
  go mostly unused.

---

## 5. One trap

`src/styles.css` carries a comment warning against re-adding an unlayered
`button { color: inherit; font: inherit }` rule. Tailwind's preflight already does
this inside `@layer base`. An unlayered duplicate outranks *every* layered utility,
which silently stopped `text-*` classes working on `<button>` elements. Leave it out.
